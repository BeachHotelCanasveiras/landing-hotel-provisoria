Visión y Objetivos del Sistema (Yield Management)\nEl hotel requiere optimizar el ingreso por habitación disponible (RevPAR) y el precio medio diario (ADR). El objetivo final es automatizar la actualización de tarifas en el PMS basándose en:\n1.  **Reglas de Ocupación Local:** Modificar precios de forma reactiva según la cantidad de habitaciones libres en Supabase.\n2.  **Rate Shopping (Inteligencia Competitiva):** Monitorear en tiempo real los precios de los hoteles competidores en Canasvieiras a través de Booking.com y Despegar.com (Decolar), ajustando nuestra tarifa a un precio marginalmente inferior (ej: -R$ 1.00) sujeto a un **Piso Mínimo de Seguridad (Floor Price)** para no vender nunca a pérdida.\n\n---\n\n## 2. Análisis de Viabilidad y Estructura de Costos\n\nDurante la auditoría del entorno para la implementación de esta fase, se identificaron dependencias críticas que introducen costos operativos mensuales que no deben ser soportados en la etapa de despegue inicial (Bootstrap) del proyecto.\n\n### A. Capa de Inteligencia Artificial (Google AI Studio vs Gemini API)\n*   **Fase de Desarrollo (Free Tier):** Google AI Studio provee acceso gratuito para prototipado y pruebas utilizando el modelo de baja latencia y alta ventana de contexto **`gemini-1.5-flash`** o **`gemini-2.5-flash`** [1.1.2, 1.1.4]. \n    *   *Límites:* Ofrece cuotas de hasta 15 peticiones por minuto (RPM) y 1,500 peticiones diarias (RPD) [1.1.3]. No se requiere tarjeta de crédito ni vincular una cuenta de facturación de Google Cloud [1.1.4].\n    *   *Privacidad:* Google puede utilizar los datos de la capa gratuita para entrenar sus modelos de IA [1.1.2, 1.1.3].\n*   **Fase de Producción (Paid Tier):** Para despliegues comerciales reales, se debe migrar al plan de pago por consumo (Pay-as-you-go) en Google Cloud [1.1.2, 1.1.8]. Esto desactiva el uso de datos para entrenamiento (garantizando confidencialidad corporativa bajo normas ISO 27001) [1.1.2, 1.1.3] e incrementa las cuotas, con un costo muy reducido por token consumido [1.1.2, 1.1.3].\n\n### B. El Desafío de la Extracción de Datos (Scraping & Proxies)\n*   **El Problema:** Las grandes OTAs (Booking.com y Despegar.com) cuentan con capas de protección de red sumamente estrictas (Cloudflare Enterprise, Akamai, etc.). Intentar descargar su HTML de forma directa desde Vercel o un servidor clásico a través de peticiones HTTP (`fetch` o `axios`) resulta en un bloqueo automático inmediato (Error 403 / CAPTCHA).\n*   **La Solución de Producción:** Para sortear estos bloqueos de red de manera estable, es obligatorio contratar un **servicio de proxies residenciales rotativos** (como *ScrapingBee*, *Crawlbase* o *Bright Data*) o consumir una API comercial de Rate Shopping (como *Channex Rate Shopper*).\n*   **Impacto de Costo:** Estos servicios operan bajo un modelo de suscripción mensual de pago (normalmente partiendo desde los $29 USD a $99 USD mensuales de base). \n*   **Decisión Estratégica:** Debido a que el proyecto opera con recursos optimizados (Bootstrap), **se pospone la codificación activa de este motor de raspado**. Se registrará este plano en la carpeta `.docs/` para que todo el desarrollo de vistas y base de datos actual se mantenga alineado con esta visión para su fácil activación futura.\n\n---\n\n## 3. Plano de Arquitectura a Implementar (Fase Futura)\n\nCuando el volumen operativo del hotel justifique los costos de infraestructura, la integración se realizará bajo la siguiente topología modular:\n\n```text\n               [ Vercel Cron / Trigger Programado ]\n                               │ (Cada 12 o 24 Horas)\n                               ▼\n               [ GET /api/cron/ai-rate-shopper ]\n                               │\n            ┌──────────────────┴──────────────────┐\n            ▼                                     ▼\n [ Descargador de Proxies ]               [ pricing_rules (Base de Datos) ]\n   • Consulta Booking/Despegar              • Lee Piso Mínimo (Floor)\n   • Evade bloqueos 403                     • Lee Margen (-R$ 1.00)\n            │                                     │\n            └──────────────────┬──────────────────┘\n                               ▼\n                [ Gemini Flash API Parsing ]\n                  • Limpia y extrae el HTML\n                  • Entrega JSON Estructurado\n                               │\n                               ▼\n               [ Algoritmo de Compensación ]\n                 • Compara competencia vs Piso Mínimo\n                 • Actualiza tabla 'rooms' (price_per_night)\n                 • Propaga a través de Webhooks\n```\n\n### A. Esquema de Base de Datos Propuesto (Supabase)\n\n```sql\n-- Tabla para guardar las reglas de negocio de tarifación por categoría\nCREATE TABLE IF NOT EXISTS public.pricing_rules (\n    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),\n    room_type TEXT UNIQUE NOT NULL REFERENCES rooms(type) ON DELETE CASCADE,\n    floor_price NUMERIC(10,2) NOT NULL DEFAULT 150.00, -- Evita vender a pérdida\n    target_offset NUMERIC(10,2) NOT NULL DEFAULT -1.00, -- Descuento marginal sobre el rival (-R$ 1)\n    is_active BOOLEAN NOT NULL DEFAULT FALSE, -- Toggle de encendido/apagado del agente de IA\n    competitor_urls JSONB, -- Enlaces directos de Booking/Despegar para el raspado\n    created_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now()),\n    updated_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now())\n);\n\n-- Tabla de histórico para auditoría analítica\nCREATE TABLE IF NOT EXISTS public.competitor_rates_history (\n    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),\n    room_type TEXT NOT NULL,\n    competitor_name TEXT NOT NULL,\n    detected_price NUMERIC(10,2) NOT NULL,\n    currency TEXT NOT NULL DEFAULT 'BRL',\n    captured_at TIMESTAMP WITH TIME ZONE DEFAULT timezone('utc'::text, now())\n);\n\n-- Políticas RLS restrictivas para asegurar confidencialidad (ISO 27001)\nALTER TABLE public.pricing_rules ENABLE ROW LEVEL SECURITY;\nALTER TABLE public.competitor_rates_history ENABLE ROW LEVEL SECURITY;\n```\n\n### B. El Endpoint Serverless Inteligente (`api/cron/ai-rate-shopper.ts`)\n*   Será un cron job que se ejecutará en segundo plano una vez al día.\n*   Consultará las reglas activas de `pricing_rules`, invocará al proxy residencial de forma segura usando variables de entorno privadas (`PROXY_API_KEY`) y entregará la estructura cruda al modelo de Gemini para procesar la respuesta en un JSON tipado.\n\n### C. Módulo en el Frontend (`RatesAvailability.tsx`)\n*   Se diseñará un panel lateral (\"aba\") que se activará al presionar un botón de \"Inteligencia Artificial\" en la barra de herramientas del PMS.\n*   Permitirá al recepcionista configurar los parámetros `floor_price` y `target_offset` sin tocar una sola línea de código, manteniendo el sistema autogestionable y escalable para marca blanca (SaaS Ready).\n\n---\n\n## 4.
